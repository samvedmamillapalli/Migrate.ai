Inspiration
What it does
Migration Oracle is an agentic database migration advisor that predicts the impact of schema changes, validates those predictions on disposable CockroachDB Cloud shadow clusters, and improves the migration predictions based on the learned outcomes. Instead of asking users to trust AI predictions alone, it proves them against reality before a migration reaches production.
Predict: Policy checks and Amazon Bedrock estimate migration duration, storage impact, rollback risk, and confidence using similar previously graded migrations.
Approve: Predictions are presented with supporting evidence so the user can decide whether to proceed with shadow execution.
Verify: AWS Step Functions and AWS Lambda create a disposable CockroachDB Cloud cluster, recreate the target environment, execute the migration, and measure actual runtime, storage changes, failures, rollback behavior, and database jobs.
Investigate: A read-only CockroachDB Managed MCP agent inspects the live shadow cluster to understand the migration's blast radius and verify what changed, with write operations blocked by design.
Grade & Remember: Migration Oracle compares predictions against actual execution, scores its own accuracy, generates embeddings with Amazon Titan, and stores the complete execution history in CockroachDB using Distributed Vector Indexing.
Improve: Future migrations retrieve the most relevant graded execution histories, allowing the system to learn from real outcomes instead of relying only on documentation or static rules.
The dashboard integrates all of the functionalities in a single workspace and allows users to connect a read-only database, generate predictions, launch shadow executions, monitor progress, inspect prediction accuracy alongside execution evidence, explore learned memories and reasoning of the AI. Slack notifications can optionally deliver important migration updates directly where teams already collaborate.
How we built it
Migration Oracle is built around CockroachDB as both its operational database and long-term memory store. The FastAPI backend manages migration runs, predictions, approvals, shadow cluster metadata, grades, and learned memories, while transaction retries ensure concurrent operations remain safe under CockroachDB's Serializable isolation.
The prediction pipeline combines policy analysis, hybrid memory retrieval using CockroachDB Distributed Vector Indexing, and Amazon Bedrock to forecast migration duration, storage impact, and rollback risk. Every prediction pauses for explicit user approval before execution begins.
Verification is orchestrated with AWS Step Functions and AWS Lambda. The workflow provisions a disposable CockroachDB Cloud cluster through the Cloud API, recreates the target schema, executes the migration, collects execution metrics, persists the results, and tears the cluster down. Secrets are securely managed with AWS Secrets Manager, while artifacts and logs are stored in Amazon S3.
After execution, a Bedrock tool-use agent connects to the CockroachDB Managed MCP Server in read-only mode to investigate the migration's blast radius. Prediction accuracy is then graded, embedded with Amazon Titan, and stored back in CockroachDB as searchable memory, allowing future migrations to learn from real execution outcomes.

Challenges we ran into
Closing the prediction loop. Generating AI predictions was the easy part. The real challenge was comparing those predictions with actual migration results, grading the model's accuracy, embedding the outcome with Amazon Titan, and storing it in CockroachDB so future predictions could learn from real execution instead of static documentation.
Managing disposable shadow clusters. Every verification run creates a temporary CockroachDB Cloud cluster, loads a representative schema, executes the migration, collects metrics, and tears the cluster down. Making that process reliable meant handling provisioning delays, limiting concurrent clusters, guaranteeing cleanup, and recovering gracefully from failures or aborted runs.
Building trust in the predictions. We didn't want Migration Oracle to be another AI tool that simply says a migration is safe. Every prediction is backed by execution evidence from the shadow run, including measured metrics, retrieved memories, and optional MCP investigation, so users can make decisions based on evidence rather than blind trust.
Getting MCP running in production. Running the CockroachDB Managed MCP Server inside an AWS Lambda workflow was very different from using it locally. Packaging the client, configuring IAM permissions for Amazon Bedrock tool use, and making the investigation best-effort so it could never fail the migration itself took several iterations to get right.
Accomplishments that we're proud of
Seeing the entire idea come to life. Watching a migration go from prediction, to shadow execution on a real disposable CockroachDB Cloud cluster, to grading, and finally becoming memory that improves future predictions made all the months of work feel worth it.
Building a product that values evidence over confidence. Instead of asking users to blindly trust an AI prediction, Migration Oracle validates every prediction against reality through shadow execution and presents the results, grades, retrieved memories, and model reasoning so users can make informed decisions.
Bringing so many moving pieces together. Integrating CockroachDB, AWS Step Functions, Lambda, Amazon Bedrock, Titan, MCP, Clerk, and our frontend into a single workflow took a lot of iteration, and seeing everything work together was incredibly rewarding.
Sharing our journey with the community. Alongside building Migration Oracle, we documented our progress through engineering blogs, sharing the architecture, design decisions, trade-offs, challenges, and lessons we learned. We hope they help others building with CockroachDB and AI, just as the community's resources helped us.
What we learned
We went into this project thinking the hard part would be building the AI. It turned out the harder part was building everything around it. A prediction only becomes useful when you can verify it, compare it with what actually happened, and learn from the outcome. That idea ended up shaping almost every part of Migration Oracle.
Cockroach University was a huge part of our learning throughout the hackathon. As undergraduate students, its self-paced courses and documentation helped us explore distributed databases far beyond what we'd covered in class. Learning about ACID transactions, Serializable isolation, transaction retries, query planning with EXPLAIN, and CockroachDB Cloud gave us a much better understanding of why distributed databases work the way they do, and we found ourselves applying those lessons over and over while building the project.
We also came away with a new appreciation for how much trust matters. We realized people shouldn't have to take an AI's word for it, especially when production databases are involved. That pushed us to build features like human approval before execution, guaranteed cleanup, evidence from shadow runs, and model traces so users can understand why the system made a recommendation instead of simply accepting it.
